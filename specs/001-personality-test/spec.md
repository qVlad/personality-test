# Feature Specification: Тест на определение типа личности (16 типов)

**Feature Branch**: `001-personality-test`
**Created**: 2026-01-04
**Status**: Draft
**Input**: User description: "Тест на 20 вопросов для определения типа личности из 16 типов. Каждый вопрос имеет варианты ответа. Система запоминает ответы, анализирует их и показывает результат с описанием типа личности."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Прохождение теста (Priority: P1)

Пользователь открывает приложение и проходит тест из 20 вопросов, последовательно отвечая на каждый. После завершения теста система анализирует ответы и показывает результат — тип личности пользователя с описанием характеристик.

**Why this priority**: Это основная функциональность приложения. Без возможности пройти тест и получить результат приложение не имеет ценности для пользователя.

**Independent Test**: Можно полностью протестировать, пройдя тест от начала до конца и проверив, что результат соответствует выбранным ответам.

**Acceptance Scenarios**:

1. **Given** пользователь открыл приложение, **When** он нажимает "Начать тест", **Then** отображается первый вопрос с вариантами ответа
2. **Given** пользователь видит вопрос с вариантами ответа, **When** он выбирает один из вариантов, **Then** выбор сохраняется и отображается следующий вопрос
3. **Given** пользователь ответил на 20-й (последний) вопрос, **When** он подтверждает ответ, **Then** отображается страница с результатом теста
4. **Given** отображается страница результата, **Then** пользователь видит название своего типа личности и описание его характеристик

---

### User Story 2 - Просмотр прогресса теста (Priority: P2)

Пользователь во время прохождения теста видит индикатор прогресса, показывающий сколько вопросов уже пройдено и сколько осталось.

**Why this priority**: Индикатор прогресса улучшает пользовательский опыт, позволяя оценить оставшееся время, но не является критичным для базовой функциональности.

**Independent Test**: Можно протестировать, начав тест и проверив корректное отображение и обновление индикатора прогресса при переходе между вопросами.

**Acceptance Scenarios**:

1. **Given** пользователь находится на вопросе N, **When** отображается экран вопроса, **Then** виден индикатор прогресса показывающий "N из 20"
2. **Given** пользователь на вопросе 1, **When** он отвечает и переходит к вопросу 2, **Then** индикатор обновляется до "2 из 20"

---

### User Story 3 - Возврат к предыдущему вопросу (Priority: P3)

Пользователь может вернуться к предыдущему вопросу, чтобы изменить свой ответ, если передумал.

**Why this priority**: Возможность изменить ответ повышает удобство, но не является критичной для получения результата.

**Independent Test**: Можно протестировать, ответив на несколько вопросов, вернувшись назад и проверив, что предыдущий ответ сохранён и может быть изменён.

**Acceptance Scenarios**:

1. **Given** пользователь находится на вопросе N (где N > 1), **When** он нажимает кнопку "Назад", **Then** отображается вопрос N-1 с ранее выбранным ответом
2. **Given** пользователь вернулся к предыдущему вопросу, **When** он выбирает другой вариант ответа, **Then** новый выбор сохраняется вместо предыдущего

---

### Edge Cases

- Что происходит, если пользователь закрывает приложение на середине теста? (Прогресс сохраняется в БД по session ID; при возвращении пользователь продолжает с места остановки)
- Что происходит, если пользователь пытается перейти к следующему вопросу без выбора ответа? (Переход блокируется, отображается подсказка выбрать ответ)
- Что происходит при попытке вернуться назад на первом вопросе? (Кнопка "Назад" скрыта или неактивна)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА отображать тест, состоящий из 20 вопросов
- **FR-002**: Каждый вопрос ДОЛЖЕН иметь минимум 2 варианта ответа для выбора
- **FR-003**: Система ДОЛЖНА позволять пользователю выбрать только один вариант ответа на каждый вопрос
- **FR-004**: Система ДОЛЖНА сохранять ответы пользователя в течение сессии прохождения теста
- **FR-005**: Система ДОЛЖНА отображать индикатор прогресса с номером текущего вопроса и общим количеством
- **FR-006**: Система ДОЛЖНА позволять пользователю вернуться к предыдущим вопросам и изменить ответы
- **FR-007**: Система ДОЛЖНА блокировать переход к следующему вопросу, если ответ не выбран
- **FR-008**: Система ДОЛЖНА после завершения теста анализировать все ответы и определять тип личности
- **FR-009**: Система ДОЛЖНА определять один из 16 типов личности на основе методологии MBTI (Myers-Briggs Type Indicator)
- **FR-010**: Система ДОЛЖНА отображать результат теста с названием типа личности (например, "INTJ - Стратег")
- **FR-011**: Система ДОЛЖНА отображать описание характеристик определённого типа личности
- **FR-012**: Описание типа личности ДОЛЖНО включать: общее описание, сильные стороны, возможные области для развития
- **FR-013**: Вопросы теста ДОЛЖНЫ быть направлены на определение 4 дихотомий: Экстраверсия/Интроверсия (E/I), Сенсорика/Интуиция (S/N), Мышление/Чувство (T/F), Суждение/Восприятие (J/P)
- **FR-014**: Система ДОЛЖНА распределять 20 вопросов равномерно по 4 дихотомиям (по 5 вопросов на каждую)
- **FR-015**: Система ДОЛЖНА сохранять прогресс теста в серверной БД и идентифицировать пользователя по session ID (cookie)
- **FR-016**: Система ДОЛЖНА позволять пользователю продолжить незавершённый тест при повторном посещении

### Non-Functional Requirements

- **NFR-001**: Интерфейс ДОЛЖЕН быть адаптивным (mobile-first) и корректно отображаться на мобильных устройствах и ПК

### Key Entities

- **Вопрос**: Текст вопроса, варианты ответа (минимум 2), принадлежность к одной из 4 дихотомий, вес каждого ответа для определения типа
- **Ответ пользователя**: Ссылка на вопрос, выбранный вариант ответа
- **Тип личности**: Четырёхбуквенный код (например, INTJ), название типа, общее описание, сильные стороны, области для развития
- **Сессия теста**: Набор ответов пользователя, текущий прогресс, результат (после завершения)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь может пройти тест от начала до конца за 5-10 минут
- **SC-002**: 100% пользователей, завершивших тест, получают результат с типом личности
- **SC-003**: Результат теста включает название типа, общее описание и минимум 3 характеристики
- **SC-004**: 95% пользователей успешно завершают начатый тест (низкий процент отказов)
- **SC-005**: Пользователь может вернуться к любому предыдущему вопросу и изменить ответ до завершения теста

## Clarifications

### Session 2026-01-04

- Q: На какой платформе должно работать приложение теста личности? → A: Веб-приложение (HTML/CSS/JS)
- Q: Должен ли интерфейс быть адаптивным для мобильных устройств? → A: Адаптивный (mobile-first)
- Q: Где хранить ответы пользователя во время прохождения теста? → A: Серверная БД (требует backend)
- Q: Должен ли прогресс теста сохраняться между сессиями браузера? → A: Да, по cookie/session ID
- Q: Какой технологический стек использовать для backend? → A: Node.js + Express + SQLite

## Assumptions

- Приложение реализуется как веб-приложение с frontend (HTML/CSS/JS) и backend (Node.js + Express + SQLite)
- Используется методология MBTI (Myers-Briggs Type Indicator) для определения 16 типов личности
- Тест не требует регистрации или авторизации пользователя
- Ответы пользователя сохраняются в серверной БД и привязываются к session ID (cookie)
- Прогресс теста сохраняется между сессиями браузера; пользователь может продолжить незавершённый тест
- Каждый вопрос имеет 2 варианта ответа, соответствующих двум полюсам одной дихотомии
- Результат определяется простым подсчётом преобладающих ответов по каждой дихотомии
